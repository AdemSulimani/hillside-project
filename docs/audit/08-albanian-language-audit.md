# Phase 8 — Albanian Language Capability Audit

> **Evidence base:** source code at commit `a8ceb15` (file:line cited throughout), the dev/staging database (6 tenants / 46+ conversations / 374+ messages / 617 products / 20 ai_alerts), and prior-phase artifacts. New evidence entries EV-030 – EV-032 (appendix-A-evidence-log.md, appended 2026-07-12); heavy reuse of EV-010/011/013/015/025/029. **No live model probing was performed** — statements about embedding-model multilingual behavior are general knowledge, and per-classifier Albanian accuracy is inferred from stored outcomes, not measured. Dev traffic is one tenant's team-test data; it demonstrates mechanisms, not production rates. Focus dialect: **Gheg Albanian as written in Kosovo messaging traffic**.

---

## Language profile of real traffic

The 40 most recent customer messages (EV-030) are effectively a corpus of informal Kosovo Gheg:

- **39/40 Albanian, 0 English.** The only English inside Albanian sentences is product/brand vocabulary ("whey protein", "nitro tech ripped", "carbo one") — exactly the tokens retrieval must match.
- **0/40 messages use Albanian diacritics.** Nobody types ë or ç. "qfar", "shije", "kushtojn", "pershendetje" are the norm; one message even misspells the greeting ("Pershendefje", EV-030).
- **Dialect markers are pervasive, not occasional:** interrogative "a" + verb ("a keni", "a muna", "a munesh", "a muni"), Gheg "ma" for standard "më" ("ma e lira", "ma qu foto", "ma shum"), deictics "qita/qito/qikjo/kto/qitynve" for standard "këto/kjo", "veq" (= vetëm), "qysh" (= si), "osht/o" (= është), "naj" (= ndonjë), "qfar" (= çfarë), clipped verbs "kushtojn/kan/jom/sun/spe di/pe don", and constant vocatives/slang ("be", "shef", "o shef qa bone", "qr") (EV-030, EV-018).
- **Misspelled brands are real:** "optium nutrition gold standart" for a catalog that holds "Optimum Nutrition …" and "Gold standard whey …" rows (EV-010 alert 45247737, EV-032).
- **The catalog side is its own dialect** (EV-031): English product names with diacritic-free Albanian attribute suffixes in nonstandard spelling ("Qokolad", "Shije Dredhze", "shije shalqini"), Albanian categories ("Shtim peshe", "Tjera (others)"), `flavor` NULL on 29/30 rows and `tags` empty on 30/30 — flavor knowledge exists only as free text inside `name`.

So the matching problem is not "Albanian query vs English catalog" — it is **unnormalized Gheg query text vs unnormalized mixed EN/AL catalog text**, with both sides spelling-inconsistent and the entire structured-attribute layer nearly empty.

## Failure examples

All four are real dev-DB incidents, not hypotheticals.

**1. "ma shum" extracted as a missing product attribute (EV-010, alert d3db5dac, 06-23).**
Customer: "A keni ma shum a veq aito / Qito" (*do you have more or only these?*). The Gheg phrasing slipped every deterministic net — 'ma shum' misses the `me shum[eë]` pattern, 'aito/Qito' miss the `(qita|keto|…)` deictic list (`productRetrievalService.ts:145,155`) — so an *inventory-browsing* question entered the product-information-gap path, whose English-prompted assessor dutifully returned `missing_info: ["ma shum"]`: the word "more" reported as an unavailable catalog fact. The customer got a partial answer about a fitness belt plus "we'll notify you shortly" about *"ma shum"*, and a specialist alert was filed.

**2. Misspelled brand defeats retrieval entirely (EV-010 alert 45247737; EV-032).**
"sa kushton qikjo optium nutrition gold standart edhe qfar shije e ka". The live catalog holds 7 matching rows ("Optimum Nutrition creatine…", "Gold standard whey…", "ON Gold standard BCAA…" — EV-032's raw 17-row count includes 10 soft-deleted duplicates its query did not filter; retrieval sees only the 7 rows with `deleted_at IS NULL`, re-verified 2026-07-12), but "optium"/"standart" produce zero ILIKE hits and the app never calls pg_trgm `similarity()` despite the index being installed for these exact columns. The fail-closed gap assessor then declared price and flavor "missing" (`missing_info: ["çmimi","shija"]`) for products whose prices sit in the catalog — an escalation manufactured by spelling distance. (Phase 7's R16 finding shows the same alert also bypasses the recommendation-question exclusion.)

**3. Keyword-less Gheg follow-ups blind the retrieval-anchored guards (EV-011, EV-013, EV-015, EV-025).**
"Pershendetje a keni carbo one" → AI: "Po." → "Me qfar shije i keni edhe sa kushtojn". The follow-up's surviving keywords (`qfar`, `shije`, `kushtojn` — 'qfar' absent from the stopword list) retrieve nothing useful; the AI still answered correctly from conversation memory ("Limon… Portokall… €18.00" — exactly the catalog prices, EV-013), and the price guard, comparing against an **empty** per-turn retrieval set (`catalogPrices: []`, `failureReason: "no_catalog_prices"`), stripped the correct answer and escalated — twice, in two conversations the same evening. The sibling case: "Cilen mkishe than ti me marr prej qitynve" (pure deixis, zero product keywords) rotated the retrieval window to 10 unrelated products and the name guard replaced the AI's recommendation of two products *it had itself listed two turns earlier* (EV-011/015, Phase 4 Trace 1). The guard mechanism is language-neutral (Phase 3's central finding), but Gheg's keyword-less deictic follow-up style **triggers it at a structurally higher rate**: this is how Albanian actually asks follow-ups.

**4. Corrupted Albanian sent to customers (EV-011).**
Both escalation fallbacks in failure 3 were delivered as mojibake: "S� shpejti do t�ju kontaktoj� nj� specialist…". A customer whose correct price answer was suppressed then received visibly broken text. The 06-23 copy of the same canned message is clean; the regression window is 06-23→06-27, and no repair/guard exists on the outbound path (`utils/textEncoding.ts` is document-ingestion-only).

## Root cause attribution

| Weakness | Primary root cause | Secondary |
|---|---|---|
| "ma shum" missing-info misfire | **entity-extraction** (English meta-prompt extracts customer-language labels with no closed vocabulary) | intent-classification (dialect regex gap let the message reach the assessor at all) |
| Misspelled-brand retrieval failure | **retrieval-recall** (no fuzzy matching; ILIKE exact-substring) | missing-normalization (no spelling folding despite installed pg_trgm) |

| Regex cue near-misses ('qito', 'ma shum', clitic 'a e keni', trailing vocatives vs `$`-anchors) | **intent-classification** (enumerative dialect regexes without morphological normalization) | — |
| Unnormalized embedding input for Gheg | **embedding-representation** (low-resource dialect, raw text, no folding; unmeasured — flagged as risk, not proven loss) | missing-normalization |

| Divergent outcomes on identical Gheg utterances (60/165) | **intent-classification** + retrieval-recall nondeterminism (Phase 3 mechanisms; Gheg input maximizes exposure) | — |

## Prioritized recommendations

Category-level only; concrete designs are deferred to Phase 16.

1. **Retrieval normalization layer (highest impact).** A shared Albanian text-normalization step (lowercase, diacritic fold, q/ç and dialect-form folding, single stopword source covering Gheg function words) applied consistently to keyword, phrase, and embedding inputs — the current three inconsistent normalizers are the root of most Albanian retrieval loss.
2. **Fuzzy lexical matching.** Use the already-installed pg_trgm `similarity()` on name/brand as a retrieval source, closing the misspelled-brand class (EV-010/032) at near-zero infrastructure cost.
3. **Guard grounding (cross-cutting with Phase 3/16).** Validate hallucination/gap guards against catalog + conversation-established facts instead of the per-turn retrieval set; Gheg's deictic follow-up style makes Albanian traffic the primary victim of the current design.
4. **Dialect-robust intent layer.** Replace enumerative deictic/comparison regexes with normalized-form matching (or route ambiguous short follow-ups to the existing LLM classifiers by default), covering the proven 'qito/aito/ma shum/clitic/vocative' leak class.
5. **Entity-extraction hardening.** Closed label vocabularies (attribute keys, not free text) for the gap assessor's `missing` output, so dialect adverbs can never become "missing product information".
6. **Outbound encoding integrity.** Extend mojibake detection (including U+FFFD) and repair to the outbound send/persist path; add a regression test on the canned Albanian messages.
7. **Catalog data quality program.** Populate `flavor`/`tags`/`brand` (they are the substrate for attribute answers and structured search); normalize name spelling variants ("Carbo One"/"Carbo one", "Qokolad").
8. **Business-rules delivery fix (from Phase 7).** The Albanian rulebook must reach all tenants, and `platform_restrictions` must actually render — most Albanian behavioral policy is currently absent from prompts.
9. **Albanian evaluation harness.** A fixed probe set of real Gheg utterances (this audit's EV-030 sample is a ready seed) run against retrieval and classifiers per release, so dialect regressions become measurable instead of anecdotal.
