# Phase 12 — Enterprise Architecture Review

> **Evidence base:** Grounded in source code (file:line), the dev/staging database, live-replay experiments (Phase 10), and the confirmed root causes of Phase 11. Dev data demonstrates mechanisms, not production incidence rates. See appendix-A-evidence-log.md.

---

## Current architecture assessment

Strip away the Express/BullMQ shell (which Phase 5 found sound) and what Hillside actually runs per inbound message is this: a **hidden imperative pipeline of ~30 LLM call sites — 15–25 serialized stochastic calls on a typical turn (Phase 10 ground truth) — wrapped around one unconstrained free-text generation** (`aiService.generateReply`, temp 0.3, no seed, no response_format — RC-03), inside a single ~4,000-line orchestrator function (`processAIReply.ts`). Every consequential business decision — escalate or answer, is this price real, is this product real, is the customer ready to order, which language to reply in — is delegated to one of those stochastic classifiers, whose noisy scalar outputs are collapsed through hard inline thresholds (0.75/0.8/0.85 — RC-08) with per-site confidence-boost quirks (RC-07), inconsistent failure policy (one fail-closed gate RC-01 sitting next to an umbrella fail-open catch spanning `processAIReply.ts:~1383–1948` — RC-19, and a swallowed order-intent throw at `:~3831` — RC-22), and zero decision-level observability.

The system is, in effect, already a multi-agent ensemble — it just hides its ~20 agents in imperative code and gives none of them a contract.

**Thesis (the fundamental architectural flaw):** *Hillside spends stochastic LLM calls where the database already knows the answer, and anchors its truth checks on the wrong reference set — so the guards designed to contain the one stochastic generation are themselves a first-order source of wrong outcomes in every corpus the audit examined (dev data demonstrates the mechanism; production incidence was not measured).* Two confirmed Critical root causes are the direct expression of this:

- **RC-01** — the escalate-or-answer decision is a fail-closed, English-prompted LLM assessor over Albanian/Gheg text; live replay escalated **8/8** runs of a plain, correctly-answerable availability question.
- **RC-02** — the price/name/gap guards validate the reply against `matchedProducts` (this turn's ~10–25 retrieved items), not the catalog; **all 3** dev "hallucination" alerts are false positives against active catalog rows (EV-011/013/015).

Much of the rest of the confirmed ledger is a corollary of the same shape (the process/CI defects — RC-23, RC-11, RC-26 — are independent of it): decisions made stochastically that state could make deterministically (RC-07/08/10/22), state that is re-derived instead of persisted (RC-13/16, 40-row window; `aiService.ts:3117` re-feeds flagged/undelivered replies as assistant turns), lifecycle without exits (RC-14 — every pause is a permanent silent dead-end; 14/20 dev alerts fire on the final turn), and side effects without atomicity (RC-20/21 — send-before-persist against a global `UNIQUE external_message_id`, `012_create_messages.sql:5`; persist-then-enqueue gap).

## Is AI used appropriately? (the mandated determinism question)

No. The audit's answer is that the LLM is used appropriately in exactly **one** place — composing Albanian prose — and inappropriately in at least **nine** business decisions that belong in deterministic backend logic, a rule engine, a state machine, or a plain DB lookup. This is the analytical heart of the phase.

| # | Decision | Current mechanism (evidence) | Why mis-placed | Deterministic alternative |
|---|----------|------------------------------|----------------|---------------------------|
| 1 | **Escalate-or-answer** | `assessProductInformationRequest()` — fail-closed English-prompted LLM over Gheg text; escalates on `!ok \|\| missing>0` and on any parse/transport error (RC-01; 8/8 false escalations in live replay) | An OpenAI transport error becomes a business decision ("escalate"); a stochastic judgment gates every answerable question | Catalog attribute-presence lookup: *does the catalog contain the asked attribute?* is a SQL check over `products` structured columns; *does the reply state it?* is inherently semantic and is verified via the declared-facts contract (see Recommendation), not free-prose parsing — with LLM reserved for genuinely ambiguous residue under an explicit fail policy |
| 2 | **Price truth** | Price-hallucination filter judges the reply against the per-turn `matchedProducts` window (RC-02); the price itself is sampled at temp 0.3 (RC-03, one replay run fabricated a "BSN" expansion that passed guards) | Retrieval rotation — a timing artifact (RC-04) — decides which true prices get stripped | Prices are `products.price / discounted_price` columns. Inject validated facts before generation; verify quoted prices by primary-key lookup against the **full active catalog** at send time |
| 3 | **Product-name truth** | Name-hallucination filter vs the same per-turn window (RC-02; all 3 dev alerts false-positive vs active rows, EV-011/013/015) | Same inversion: the reference set is a volatile retrieval snapshot, not the catalog | Fold/trigram match against a normalized full-catalog fact index (`pg_trgm` is installed and currently dormant — Phase 10/WF-G: `similarity()` called 0 times) |
| 4 | **Availability / attribute truth** | Attribute-intent + availability classifiers, English prompts over Albanian (RC-25; EV-010: Gheg "ma shum" escalated as a missing product attribute) | "Does a 2kg vanilla variant exist?" is a WHERE clause, not a judgment call | SQL over structured columns (`flavor/size/color/variant`, `in_stock`) with diacritic-folded, Gheg-normalized keys — noting that *parsing* the free-text ask into attribute keys stays semantic (it belongs to the single structured slot-extraction call); only the existence *decision* becomes the WHERE clause |
| 5 | **Order-field completeness & affirmation** | 7-conjunct gate over boosted-confidence LLM booleans (intent>0.85 + product+phone+name+address+affirmation), with the affirmation detector missing the confidence boost the four escalation detectors have (RC-07, RC-08, RC-22) | The same model quirk (absent confidence field) over-escalates and under-creates orders — an asymmetry engineered by per-site boost code, not by meaning | Persisted `order_stage` state machine + slot completeness check on durable slots (E.164 phone regex, non-empty address) + a normalized consent lexicon (`po`, `dakord`, `po e marr`, Gheg forms) for the high-precision head — affirmation phrasing outside the lexicon is genuinely semantic (conditional, sarcastic, novel Gheg forms) and routes to the structured slot-extraction call with a declared fail direction (no silent order creation), not to pure code |
| 6 | **Comparison / recommendation grounding** | Free generation over whatever retrieval surfaced this turn; the `product_ids` anchor empties on order-flow/escalation replies and facts slide out of the 40-row window (RC-13 — 10 anchor-loss events documented in Phase 4; RC-04 makes the retrieved set itself a per-worker coin-flip) | What was recommended is a fact the system itself created; re-deriving it from prose is lossy by construction | Persist `last_recommended_product_ids` in a conversation-state store, always injected; re-ground any anchored product by ID lookup at any depth |
| 7 | **Pause / resume lifecycle** | Pauses are entered stochastically (LLM escalations, RC-01/08) and never exited: no auto-resume exists for `ai_paused`, rate-limit pauses, or `human_override_until` (RC-14); the rate counter INCRs per job *attempt* before gates (`processAIReply.ts:~1231`, RC-18), so retries/stale jobs exhaust 25/h and strand the conversation | A lifecycle is a state machine; today it is four uncoordinated columns + Redis + BullMQ with six catalogued dead-end states and no exit transitions | Explicit persisted FSM where every non-terminal state declares a non-human exit (timer, inbound, alert-resolve-default-resume); counter increments only on real sends |
| 8 | **Commission eligibility (money)** | `hasHumanParticipationInCurrentOrderWindow()` evaluated `NOW()`-relative *post-send* behind the LLM-boolean gate (RC-22); IG/FB self-echo misclassified as human on any Redis registry miss (`webhookNormalizer.ts:92`, `outboundEchoRegistry.ts:53` fails to `human` — RC-24), silently killing use-case fees | Billing outcomes currently depend on job scheduling latency and a TTL'd cache read — nondeterministic revenue | Compute eligibility as a fold over **stored, ordered event timestamps**; self-echo resolved by durable lookup of the echo's `external_message_id` against persisted outbound sends |
| 9 | **Reply language** | Temp-0 LLM/heuristic per turn with a hard `'sq'` default (RC-10); ambiguous English gets Albanian on one run, English on another | Language is sticky per contact/conversation, not a per-turn inference | Channel/contact locale → normalized marker rule → persisted sticky slot; `'sq'` only when genuinely unknown |

**Count: 9 LLM-delegated decisions to move into deterministic logic.** Precision on that claim: in rows 1, 4, and 5 it is the *decision* (existence, completeness, truth) that becomes deterministic — the *parse* of Gheg free text into structured slots is irreducibly semantic and is exactly the narrow extraction call in (b) below, not an assertion that NLU disappears. The residual, legitimate LLM surface is small: (a) the single prose generation, (b) narrow structured slot extraction, (c) an ambiguity-only sensitive-intent classifier with a declared fail-closed policy, and (d) offline fluency/quality evaluation. Note that the current quality-eval model (RC-15: threshold 0.1 vs `.env.example` 0.6, systematic 0.200 false-low on order confirmations) is a tenth LLM decision that should simply be *removed* from the send path rather than moved.

## Candidate architectures

Three full-depth candidates were designed against the 22 CONFIRMED + 3 WEAKENED root causes (see `scratchpad/audit/arch/`). All three independently converge on the same three moves — validate facts against the full catalog, persist conversation state as slots, make pauses auto-resume — which is itself strong evidence about where the truth lies.

### Candidate A — Deterministic Pipeline with Consolidated Gate

Deterministic backend owns every fact and routing decision a lookup or persisted state can answer (order-stage machine, Gheg lexicons, locale resolution, structured-column availability), wrapping **exactly one grounded generation** (temp 0 + seed + `response_format`, model emits `{facts_used[], prose}`), validated by **one consolidated grounding gate against a materialized full-catalog fact index** — never against `matchedProducts`. Adds receipt-time gate/config snapshots, a transactional outbox, an explicit resumable FSM, and a persisted slot store. **Disposition: Eliminates 18 / Mitigates 5 / N/A 1 (RC-23)** — both Criticals (RC-01, RC-02) and both issue drivers (RC-01, RC-14) eliminated. Chief new risks: gate fact-extraction becomes the new crux (mitigated by the `facts_used` declaration contract), Gheg lexicon coverage becomes a maintenance surface, and determinism ≠ correctness (a wrong lexicon entry now fails identically every time).

### Candidate B — Event-Driven Workflow Engine with Typed State

Event-sourced per-conversation machine: every fact is an immutable Zod-validated event in `conversation_events` (`UNIQUE(conversation_id, seq)` as the serialization primitive); LLMs are typed *nodes* with declared timeout/retry/fail-direction; all business decisions are pure `decide(state, event, policy)` transitions that replay byte-identically; effects run through a same-transaction outbox; a boot-time validator rejects any state without a non-human exit (the structural negation of RC-14's six dead ends). No Kafka/Temporal — a TS library + three Postgres tables. **Disposition: Eliminates 13 / Mitigates 8 / N/A 3 (RC-09, RC-23, RC-25).** Strongest candidate on observability (the log *is* the trace), atomicity (RC-19/20/21/22), and testability (golden replay in CI). Chief cost: a genuine event-sourcing paradigm tax on a 1–2-engineer team, a ~4–6-month strangler migration, and a dual-write hazard mid-migration — its author flags Phases 4–5 as where the paradigm cost concentrates and Phases 1–3 as independently low-regret.

### Candidate C — Single Orchestrator Agent with Tool-Calling

One LLM orchestrator turn loop (temp 0, seed, strict schemas, max 4 iterations, `parallel_tool_calls=false`) over ~7 **deterministic, server-authoritative tools** (`catalog_search`, `product_details`, `check_availability`, state read/write, `draft_order`, `escalate`, templated handoff). The model decides *what to look up and which action to take*; the server decides *what is true and what is allowed* — every cited price/product verified by primary-key lookup against the full catalog before send, plus a tiny deterministic Gheg/sq/en refund-cancellation net that fails closed only for that enumerated class. **Disposition: Eliminates ~11 / Mitigates 9 / N/A 5 (the ingestion/process RCs — 09, 11, 21, 23, 24 — bundled as substrate, honestly not consequences of the pattern).** Its honest self-assessment: net determinism *gain on outcome classes* versus today (1–3 planning decisions vs 18–25 chained threshold gates), but no bit-reproducibility, deepened single-model dependency, tool-choice behavior sensitive to silent model revisions (hard dependency on a CI eval harness that RC-23 says does not run), and the model may under-call tools.

## Recommendation

**Recommended target: a hybrid — Candidate A (Deterministic Pipeline with Consolidated Gate) as the decision/validation core, built on Candidate B's substrate primitives (transactional outbox, receipt-time snapshot, append-only decision ledger — B's Phases 1–3 only, no full event sourcing), with Candidate C's tool-grounding adopted inside A's single generation stage (the model declares `facts_used` / may call `product_details`-style lookups, server verifies by primary key). Explicitly rejected: full event sourcing (B Phases 4–5) and any multi-agent topology.**

Justification against the confirmed root causes:

- **The two Criticals are closed by A's spine — each with one stated dependency.** The consolidated gate validating against a full-catalog fact index eliminates RC-02's confirmed failure mode (false flags against active catalog rows; replays of EV-011/013/015 must return zero flags — that is the acceptance test), *contingent on the `facts_used` declaration contract holding* — falling back to free-prose fact extraction would reintroduce the same defect against a better reference set. Replacing the fail-closed gap assessor with a catalog attribute-presence check eliminates RC-01's confirmed failure class (stochastic fail-closed gating of catalog-answerable questions — the 8/8 replay); questions the structured catalog cannot answer still route to an LLM residue, so a bounded stochastic escalation surface remains — under an explicit, per-site fail policy rather than none. No other single move closes more confirmed severity.
- **The Issue-2 driver is eliminated by A's FSM.** Auto-resume as a first-class transition + send-time-only rate INCR closes RC-14/RC-18 — with resume policy declared per pause reason (rate-limit and low-confidence pauses may exit on timer/inbound; sensitive-escalation pauses exit only via alert resolution, so RC-14's fix cannot resurrect RC-19's failure class); the persisted slot store closes RC-13; delivery-status-filtered history closes RC-16.
- **B's substrate closes the atomicity family cheaply.** Outbox + idempotency keys + receipt-time snapshots close RC-20/21/06/11/17 and give A the durable decision ledger that makes RC-24's echo check a lookup instead of a TTL'd cache. These are B's independently-low-regret phases; the paradigm tax lives entirely in the phases we reject.
- **C's grounding contract de-risks A's biggest new risk.** A's honest self-critique is that deterministic fact-*extraction* from Gheg prose is itself an NLP problem; C's structured declaration (`cited_products`/`facts_used`, verified by PK lookup) converts extraction into declaration-compliance — the one place C is strictly better than A.
- **Small-team reality.** Hillside is 1–2 backend engineers with a CI pipeline that runs no tests and a deploy that races CI (RC-23). Full event sourcing is a 4–6-month paradigm migration whose dual-write window reintroduces exactly the divergence being fixed; a free-roaming agent loop bets customer-facing correctness on an eval harness that cannot run today. The hybrid's steps are each independently shippable behind a feature flag, and steps 1–2 (fact index + guard repoint; outbox + snapshot) already neutralize both Criticals. **RC-23 (CI gate, `npm test` in CI, migration-runner fix) is a Week-0 prerequisite for all of it — migrating architecture on an ungated pipeline is malpractice.**

**Where specialized agents genuinely help vs where multi-agent worsens things:** The audit's most important negative result is that Hillside already *is* a ~20-agent system — one hidden stochastic classifier per decision — and that shape is precisely what produced 60 divergent-outcome pairs in 165 near-identical inputs (Q9) and 8/8 false escalations (RC-01). Divergence compounds multiplicatively across serialized stochastic gates; adding planner/critic/router agents would multiply it further while adding latency and token cost. Specialized LLM use *is* justified in exactly four bounded roles: (1) the single grounded prose generation; (2) narrow structured slot extraction (one schema call per turn, declared fail direction); (3) an ambiguity-only sensitive-intent classifier behind the deterministic Gheg cancel/refund lexicon, fail-closed with its own catch (never RC-19's umbrella); (4) **offline** evaluation/fine-tuning corpus work (Gheg fluency scoring, golden-set regression) — off the send path entirely, where RC-15's miscalibration can do no billing damage.

**Migration direction** (direction only — detailed implementation is Phase 16): (0) RC-23 CI/deploy/migration fixes; (1) catalog fact index + repoint both Critical guards (RC-02/01), acceptance = zero false flags on the EV-011/013/015 replay corpus; (2) outbox + receipt-time snapshot + idempotency (RC-20/21/06/11/17); (3) FSM auto-resume + slot store (RC-14/13/18/16); (4) deterministic routing collapse behind per-class feature flags, retiring the classifier sprawl per Phase 6 dispositions (RC-05/07/08/10/22); (5) single grounded generation with declared facts + prompt hygiene (RC-03/25/26). Each step independently shippable and replay-testable.

## Sub-audits

**RAG / retrieval architecture.** Hybrid fusion (pgvector cosine + keyword) with no reranker, a global HNSW-style index, and — the structural defect — grounding applied *after* generation against the per-turn window instead of *before* generation against the catalog (RC-02). The vector arm barely functions: `text-embedding-3-small` rarely clears the 0.65 threshold (EV-043), the 5s non-aborting `Promise.race` drops the semantic arm silently per worker with no negative caching (RC-04), and the installed `pg_trgm` indexes are dormant (`similarity()` called 0 times, WF-G). Direction: demote retrieval to candidate-supplier, ground on a materialized full-catalog fact index, add aborting timeouts + a `semanticSkipped` metric, and revisit the embedding model/threshold as tuning, not architecture.

**Memory architecture.** There is no memory design — short-term memory is the last 40 rows by `conversation_id`, session memory does not exist, and long-term facts (name, phone, address, allergies, last recommendation) slide out of the window as depth grows (RC-13, 10 documented anchor-loss events). Worse, the history is contaminated: `aiService.ts:3117` maps every non-customer row to `assistant` regardless of `flagged` or delivery status, so the model conditions on its own blocked/phantom output (RC-16). Direction: a persisted, versioned slot store always injected regardless of depth, plus delivery-filtered transcript assembly.

**Prompt architecture.** The system prompt is 26–33K characters and unbudgeted while only history is token-budgeted; an orphan admin-created `offers_promotions` block (absent from migrations, catalog-inactive) injects ~1,478 chars referencing a nonexistent "Active offers" section into 6/6 tenant prompts; five in-prompt rules (R6/R13/R16/R17) are contradicted by the post-hoc guards; and the business-rule footer reaches 1 of 6 tenants (RC-26, RC-25). Twenty migrations of prompt-block churn with no allowlist or budget assertion is how the orphan got in. Direction: allowlisted, token-budgeted, versioned prompt assembly with required-section assertions.

**Observability.** Decisions leave no artifact: no classifier scores are logged, escalation reasons are not traceable to inputs, silent drops number 32 distinct paths, and RC-21's persist-without-enqueue produces inbox-visible messages the AI never saw with zero signal. Sentry (`hillside-6c`) holds no meaningful history. Every candidate independently concluded the same fix: an append-only per-turn decision ledger (snapshot, scores, reference sets, verdicts, policy version) so "why did this escalate?" becomes a query. Phase 15 details the gap inventory.

**Determinism strategy.** There is none: the main generation runs at temp 0.3 with no seed and no response_format (RC-03, distinctRepliesPerInput up to 8), classifiers ride knife-edge thresholds with asymmetric confidence boosts (RC-07/08), burst composition is an 8s scheduler race (RC-05), gates are read ≥8s after receipt (RC-06), and even config identity drifts across workers within a 900s delete-only cache (RC-17). The strategy must be: determinism owns facts and routing; stochasticity is confined to prose composition and contained by a catalog-grounded gate; temp 0 + seed is a mitigation, not a guarantee (no bit-reproducibility on hosted models). Phase 13 inventories every source.

**Reliability / fault-tolerance.** The failure posture is incoherent by count: 6 fail-closed, 79 fail-open, 32 silent-drop sites, with the entire pre-reply escalation subsystem fail-open as a unit (RC-19 — a refund demand degrades to a sales reply on any transient error) while the one fail-closed gate escalates correct answers (RC-01). Retry is non-idempotent (RC-20 dead-letters delivered replies on the global UNIQUE; RC-21 loses jobs artifact-free; RC-18 burns the rate budget on attempts). Direction: transactional outbox, per-decision declared fail directions, idempotency keys, and auto-expiring pauses.

**Scalability.** The binding constraint is not Postgres or Redis — it is 15–25 serialized OpenAI completions per message, which sets both the latency floor and the concurrency ceiling (per-tenant Redis slots exist precisely to ration it). Collapsing to 1–2 completions per message (the recommendation) is simultaneously the scalability, latency, and cost fix; the added DB work rides already-installed indexes. Event-log growth (if the ledger is adopted) is trivial at hundreds-of-tenants scale but needs an archival owner.

**Security model.** Application-level tenant isolation is undermined at the webhook seam: `findChannelByTypeAndExternalId` (`channel.ts:120`) is tenant-unscoped, LIMIT 1, no ORDER BY, and the UNIQUE key includes `tenant_id`, so nothing prevents dual-connection routing a business's customers to another tenant (RC-09, latent — dev table empty). The echo registry fails toward `human` (RC-24), corrupting billing state, and webhook freshness trusts `Date.now()` fallback (RC-11). Direction: global `UNIQUE(type, external_id)`, receipt-time tenant binding, durable outbound-send registry, dedupe-based replay protection.

**Cost model.** Spend is call-count-dominated: ~20 classifier calls per message purchase decisions the database already knows, and revenue-bearing computations (commission, use-case fees) are themselves nondeterministic — `NOW()`-relative windows post-send (RC-22) and echo-misclassification silently zeroing use-case fees (RC-24) mean the billing ledger cannot be trusted to reproduce. Direction: ~10× per-message completion reduction plus billing as a deterministic fold over stored timestamps, making every invoice line replayable.

**Maintainability.** A 4,000-line orchestrator with 30 embedded stochastic call sites, per-site threshold/boost constants, duplicate out-of-order migrations (062–065), 548 tests that CI never executes, and a deploy that races CI (RC-23) — behavior change is currently unreviewable and unregressable. The highest-leverage maintainability investment identified by this audit is not code style but the determinism itself: pure decision functions + golden replay corpora built from the audit's own evidence (IN1/IN3, EV-010/011/013/015) turn every confirmed RC into a permanent regression test — provided RC-23 is fixed so CI actually runs them.
